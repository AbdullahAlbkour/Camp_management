# نظام إدارة مخيمات اللجوء

نظام ويب إداري لإدارة مخيمات اللجوء المحلية: تسجيل اللاجئين والأسر، توزيع السكن،
المساعدات الإنسانية، السجلات الطبية، حركة الدخول والخروج، والتقارير الأمنية —
مع سجل تدقيق كامل وصلاحيات دقيقة حسب الدور.

مبني بـ **Laravel 12** و **MySQL 8** وواجهة **Blade** عربية RTL بالكامل، بدون أي
خطوة بناء للواجهة الأمامية (CSS و JavaScript عاديان).

## التشغيل السريع

### باستخدام Docker

```bash
docker compose up -d --build
```

ثم افتح <http://localhost:8000>. الحاوية تنتظر قاعدة البيانات، تنشئ مفتاح التطبيق،
تشغّل الهجرات، وتُشغّل المجدول تلقائيًا.

### التشغيل المحلي

```bash
make setup    # نسخ .env، تثبيت الاعتماديات، توليد المفتاح، الهجرة والبيانات الأولية
make serve    # http://localhost:8000
```

أو يدويًا:

```bash
cp .env.example .env
composer install
php artisan key:generate
php artisan migrate --seed
php artisan serve
```

### بيانات ضخمة للتجربة

```bash
php artisan db:seed --class=DemoLargeDatasetSeeder
```

ينشئ 2000 لاجئ و200 أسرة و10 مخيمات مع سجلات طبية وأمنية وحركة ومساعدات.

## قواعد العمل المفروضة في النظام

هذه ليست تعليمات في الواجهة فقط — النظام يرفض العمليات المخالفة:

- **السعة**: لا يمكن تخصيص لاجئ لوحدة ممتلئة أو تحت الصيانة، ولا لوحدة تتبع مخيمًا آخر.
- **تقليل السعة**: لا يمكن تقليل سعة وحدة إلى أقل من عدد ساكنيها الحاليين.
- **أثر السكن**: أي تغيير في المخيم أو الوحدة — من شاشة النقل أو من تعديل الملف —
  يُسجَّل في `residency_transfers`. لا يوجد مسار يغيّر السكن بصمت.
- **الحركة ليست نقلًا**: الدخول والخروج يغيّران حالة الوجود فقط، ولا يمسّان السكن.
- **المستفيد الواحد**: المساعدة ترتبط بلاجئ أو بأسرة، وليس الاثنين معًا ولا لا أحد.
- **التواريخ**: لا ميلاد ولا توزيع ولا حركة ولا تقرير في المستقبل، ولا متابعة طبية
  قبل تاريخ الزيارة نفسها.
- **الأرشفة**: لا يمكن أرشفة مخيم يضم لاجئين فعالين، ولا وحدة مسكونة، ولا أسرة لها أفراد.

## البحث والفلترة في صفحات القوائم

صفحات اللاجئين والأسر والوحدات السكنية تشترك في شريط فلترة واحد:

- **بحث عربي متسامح**: البحث عن «احمد» يجد «أحمد»، و«فاطمه» تجد «فاطمة»، و«يحيي» تجد
  «يحيى». يُطبَّق التطبيع نفسه على النص المخزَّن وعلى ما يكتبه المستخدم، فيتجاهل الهمزة
  والتشكيل والتطويل، ويقبل الأرقام العربية (`١٢٣` = `123`).
- **البحث بالاسم أو رقم الوثيقة أو الهاتف أو رمز البطاقة** من صندوق واحد.
- **فلاتر متقدمة** تُطوى افتراضيًا وتُفتح تلقائيًا إن كان أحدها مطبقًا:
  المخيم، حالة السكن، الوجود، الجنس، حالة السجل، الفئة العمرية، ومدة البقاء بلا سكن.
  وللأسر: المخيم، عدد الأفراد، حالة سكن الأفراد، والأسر بلا رب أسرة. وللوحدات:
  المخيم، النوع، الحالة، الإشغال (فارغة / فيها متسع / ممتلئة)، والسعة.
- **ترتيب** بالنقر على رأس العمود، مع الحفاظ على الفلاتر المطبقة.
- **شارات الفلاتر المطبقة** أعلى الجدول، كل واحدة تُزال بنقرة.
- **عدد الصفوف** في الصفحة (20 / 50 / 100)، والفلاتر تبقى محفوظة عبر صفحات النتائج.

**ملاحظة تقنية**: التطبيع العربي يُحسب مرة واحدة عند الحفظ ويُخزَّن في العمود
`refugees.search_text`. جُرِّب أولًا تطبيقه داخل الاستعلام نفسه، لكن التعبير عنه
بسلسلة `REPLACE()` متداخلة يتجاوز حد مكدّس المحلّل في SQLite، ويُعاد تنفيذه لكل صف
عند كل بحث. الحساب عند الكتابة يكلّف عمودًا واحدًا ويجعل المقارنة `LIKE` بسيطة.

## الخصوصية والحماية

النظام يتعامل مع بيانات شخصية لفئة هشّة، ومبني على ذلك:

- **حماية على مستوى العمود**: المدير يرى أن زيارة طبية حدثت وأن متابعة مستحقة، لكن
  عمود التشخيص لا يظهر له أصلًا — لا يُعرض فارغًا. المبدأ نفسه ينطبق على وصف الحوادث الأمنية.
- **المرفقات الطبية** تتبع القاعدة نفسها: الكادر الطبي ومدير النظام فقط.
- **الملفات المرفوعة** تُخزَّن على قرص خاص باسم مولَّد، وتُقدَّم فقط عبر مسار يعيد
  التحقق من الصلاحية — تسريب المسار لا يعني تسريب الملف.
- **سجل التدقيق** ينقّي كلمات المرور والتشخيصات وأوصاف الحوادث من بيانات السياق.
- **التصدير والطباعة وطباعة البطاقات** كلها مسجّلة، مع الفلاتر المطبقة — لأن التصدير
  يُخرج بيانات شخصية من النظام.
- **حماية الدخول**: تحديد المحاولات لكل (بريد + عنوان)، إقفال مؤقت، تسجيل كل محاولة
  فاشلة، وتنبيه لمدير النظام عند الإقفال.
- **سياسة كلمات مرور موحّدة** في كل مسار: إنشاء المستخدم، التغيير الذاتي، ورابط الاستعادة.
- **الجلسات**: تغيير كلمة المرور ينهي الجلسات الأخرى، وتعطيل الحساب يُخرج المستخدم
  من أول طلب تالٍ.
- **استعادة كلمة المرور** لا تكشف إن كان البريد مسجلًا أم لا.

## المهام المجدولة

</div>

```bash
php artisan camps:daily-digest        # يوميًا 06:30
php artisan camps:prune-audit-logs    # أسبوعيًا
php artisan camps:rebuild-search      # عند الحاجة بعد استيراد جماعي
```

<div dir="rtl">

- **`camps:daily-digest`** يرفع تنبيهات للحالات التي لا يكتشفها أحد لأنها تتعلق بمرور
  الوقت لا بفعل مستخدم: متابعات طبية استحقت (ومتأخرة بشكل منفصل)، لاجئون بلا سكن منذ
  مدة، من خرج من المخيم ولم يُسجَّل رجوعه، ووحدات وصلت السعة.
- **`camps:prune-audit-logs`** يطبّق سياسة الاحتفاظ: يحذف الضجيج منخفض الحساسية بعد
  المدة المحددة، **ولا يحذف أبدًا** السجلات عالية الحساسية أو الحرجة.
- **`camps:rebuild-search`** يعيد بناء فهرس البحث العربي. لا يحتاجه التشغيل العادي —
  النظام يحدّث الفهرس مع كل حفظ — لكن الإدخال الجماعي عبر `DB::table()->insert()`
  يتجاوز أحداث النموذج، فتصبح السجلات المستوردة غير قابلة للبحث حتى يُشغَّل هذا الأمر.
  استخدم `--check` لمعرفة إن كان الفهرس مكتملًا.

المجدول يعمل تلقائيًا داخل Docker. خارجه أضف إلى `crontab`:

</div>

```cron
* * * * * cd /path/to/project && php artisan schedule:run >> /dev/null 2>&1
```

## التطوير والاختبار

</div>

```bash
make check   # يشغّل ما يشغّله CI: فحص الأسلوب + كل الاختبارات
make test    # الاختبارات فقط
make lint    # فحص الأسلوب فقط
make fix     # تطبيق تنسيق Pint
```

<div dir="rtl">

الاختبارات تعمل على SQLite في الذاكرة ولا تحتاج قاعدة بيانات. التغطية تشمل قواعد
النطاق (السكن، المساعدات، الطبي، الأمن)، مصفوفة الصلاحيات كاملة عبر المسارات،
المصادقة وتحديد المحاولات، التصدير، البحث، المرفقات، والأرشفة.

خط CI يشغّل فحص الأسلوب، ومجموعة الاختبارات على PHP 8.2 و8.3 و8.4، ويشغّل الهجرات
ثم يتراجع عنها على MySQL حقيقي — لأن المخطط يحوي قيود `CHECK` خاصة بـ MySQL.

## البنية

</div>

```text
app/
├── Console/Commands/    المهام المجدولة (الملخص اليومي، سياسة الاحتفاظ)
├── Http/
│   ├── Controllers/     تنسيق فقط — قواعد العمل في الخدمات
│   ├── Middleware/      RoleMiddleware، حالة الحساب، ترويسات الحماية
│   └── Requests/        قواعد التحقق، مصدر واحد لكل موديول
├── Models/              Eloquent مع العلاقات والحذف الناعم
├── Reports/             سجل التقارير، الأعمدة، والمصدِّر
├── Rules/               سياسة كلمة المرور
├── Services/            قواعد العمل: السكن، التسجيل، المساعدات، الطبي، الأمن،
│                        التنبيهات، التدقيق، الأرشفة، المرفقات، البحث
└── Support/             Code128، XlsxWriter، تسميات القيم العربية
```

<div dir="rtl">

**المبدأ**: المتحكمات تنسّق ولا تقرر. أي قاعدة عمل تعيش في خدمة داخل معاملة قاعدة
بيانات، لتبقى محفوظة مهما كان المسار الذي وصل إليها — شاشة، أمر، أو اختبار.

**بدون اعتماديات إضافية**: تصدير Excel و باركود Code 128 مكتوبان داخل المشروع
(`app/Support/`)، فلا حاجة لمكتبة جداول أو مكتبة رسم — وهو ما يُبقي النشر على أجهزة
محلية بسيطًا.
